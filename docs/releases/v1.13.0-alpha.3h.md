# Version 1.13.0-alpha.3h — Roster Performance Stabilization

This stabilization build fixes the primary slowdown introduced by Alpha.3g and hardens roster loading.

## Corrected

- Roster schema normalization now writes only when data actually changes. Alpha.3g rewrote `rosters.json` during every roster read.
- Roster snapshots are now created only for real roster mutations, preventing thousands of redundant backup files.
- Recovery scanning runs once per process and is bounded to known backup folders instead of recursively scanning the parent installation tree.
- Roster data is cached using the file modification timestamp and returned as defensive copies.
- Roster writes are atomic and skip unchanged payloads.
- The roster API loads the school database once instead of once per roster.
- Operator mutations no longer perform an immediate duplicate `/api/state` request and duplicate full UI render.
- Opening play entry reuses the roster cache instead of forcing a roster download every time.

## Data safety

Alpha.3g recovery behavior remains available. This build does not invent missing roster records; it restores only from surviving backups.
